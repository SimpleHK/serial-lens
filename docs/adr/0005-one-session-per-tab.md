# One session per tab: monitored ports and opened log files

The monitor view runs one session per tab instead of a single shared controller. A **port session** owns its own `MonitorController` (so several ports stream simultaneously) and its own log-to-file state; a **file session** is a read-only snapshot of an opened `.log`/`.txt` file fed through the same append pipeline (cap included: only the newest `maxBufferLines` lines are kept). Every host→webview state/append/logging message carries a `sessionId`; the webview keeps per-tab buffers, scroll position, and Follow/Lock state, and switches tabs by re-rendering the virtualized window. Tags, filter mode, and timestamps stay global display choices shared by all tabs — a filter change re-decides every tab's lines. The public API maps onto the same sessions (`startMonitoringPort` opens one; its tab outlives `stopMonitoring` until closed). Reconnecting a stopped tab opens a new session that replaces the old tab only once it connects, so a failed open never destroys the previous buffer.
