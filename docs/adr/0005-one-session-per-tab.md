# One split-view pane per session: monitored ports and opened log files

The monitor view runs one session per split-view pane instead of a single shared controller. A **port session** owns its own `MonitorController` (so several ports stream simultaneously, side by side) and its own log-to-file state; a **file session** is a read-only snapshot of an opened `.log`/`.txt` file fed through the same append pipeline (cap included: only the newest `maxBufferLines` lines are kept). Every host→webview state/append/logging message carries a `sessionId`; the webview keeps per-pane buffers, virtualized renderers, scroll position, and Follow/Lock state. The toolbar acts on the **focused pane** (click to focus; accent outline); ＋ or Start opens another monitor and the view splits wider (narrow viewports scroll horizontally). Tags, filter mode, and timestamps stay global display choices shared by all panes — a filter change re-decides every pane's lines. The public API maps onto the same sessions (`startMonitoringPort` opens one; its pane outlives `stopMonitoring` until closed, and several API monitors may run at once). Reconnecting over a stopped pane opens a new session that replaces the old pane only once it connects, so a failed open never destroys the previous buffer.
