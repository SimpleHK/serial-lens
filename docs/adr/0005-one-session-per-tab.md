# One split-view pane per session: monitored ports and opened log files

The monitor view runs one session per split-view pane instead of a single shared controller. A **port session** owns its own `MonitorController` (so several ports stream simultaneously, side by side) and its own log-to-file state; a **file session** is a read-only snapshot of an opened `.log`/`.txt` file fed through the same append pipeline (cap included: only the newest `maxBufferLines` lines are kept). Every host→webview state/append/logging message carries a `sessionId`; the webview keeps per-pane buffers, virtualized renderers, scroll position, and Follow/Lock state. **Each pane is fully self-contained**: its bar embeds the serial config (port, baud, data bits, parity, stop bits, line ending) and the pane actions (start/stop, send-bar toggle, clear, log-to-file, export, follow/lock, find, close); edits become the pane's settings. The PORT is locked while connected, but parameter edits (baud/data bits/parity/stop bits) **auto-reconnect** the session in place via a `reconnect` host message — same pane, same buffer, MS-parity live reconfiguration. ▶ on a stopped pane restarts with the pane's settings, replacing the pane only once the new session connects. The global actions (＋ add monitor, refresh, tag filter, timestamps, log directory, open file, tag from selection, manage, status) exist as ONE `#global-seg` segment that rides the **focused pane's bar** (or the empty-state row) — the winning variant of the toolbar-layout prototype (`prototype/toolbar-layout` branch): a left rail and a compact stack lost to the contextual model, which costs zero vertical space. ＋ opens a port quick-pick that clones the newest pane's settings. The send bar starts collapsed (mostly unused) and toggles per pane. The public API maps onto the same sessions (`startMonitoringPort` opens one; its pane outlives `stopMonitoring` until closed, and several API monitors may run at once).

Find is a pane-local, editor-style widget (Ctrl+F or the pane's magnifier): match-case / whole-word / regex toggles, occurrence counter, prev/next navigation, and text-level match highlighting through the CSS Custom Highlight API — so highlights never touch the DOM text nodes and text selection (tag creation) keeps working. Occurrences are computed over the pane's *visible* lines in rendered-text coordinates, recomputed on query edits, appends, filter changes, and timestamp toggles.
